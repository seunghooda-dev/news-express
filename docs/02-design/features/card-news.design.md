# 카드뉴스 발행 (card-news) — Design

- **작성일**: 2026-08-09
- **선행 문서**: [Plan](../../01-plan/features/card-news.plan.md)
- **전제**: 전달은 자체 웹, 하루 3~5건 엄선, 4:5 상하 분할 레이아웃

## 1. 전체 흐름

```
수집·초안 (기존)
     │
     ▼
① 후보 추천      하루치 초안 중 8건을 점수 규칙으로 고른다  (읽기 전용)
     │
     ▼
② 관리자 확정    사람이 3~5건을 고른다                   (기존 검수 화면 옆에)
     │
     ▼
③ 문안 생성      초안 → 표지 문구 + 본문 카드 3~4장       (Gemini, 읽기 전용)
     │
     ▼
④ 카드 합성      1080×1350 PNG 세트                      (Pillow, 디스크 저장)
     │
     ▼
⑤ 공개           /card-news 에서 주민이 본다              (로그인 불필요)
```

**기존 파이프라인을 건드리지 않는다.** ①③은 초안을 읽기만 하고, ④는 결과를
디스크에 따로 쌓는다. 수집·초안 생성 경로에 손대지 않으므로 회귀 위험이 낮다.

## 2. 카드 사양

| 항목 | 값 | 근거 |
|---|---|---|
| 크기 | **1080 × 1350** (4:5) | 모바일 세로 화면을 가장 크게 쓴다. 인스타로 확장할 때도 그대로 쓸 수 있다 |
| 장수 | 표지 1 + 본문 3~4 | 초안이 3~6문장이라 자연스럽게 맞는다 |
| 표지 | 상단 58% 사진 + 하단 제목·출처 | 시안에서 검증 |
| 본문 | 상단 42% 사진(있으면) + 문구 | 사진이 부족하면 텍스트만 |
| 사진 배치 | **폭에 맞추고 좌우는 절대 안 자른다.** 높으면 위아래만 자르고, 낮으면 위아래를 배경으로 채운다 | 초기 구현이 밴드를 꽉 채우느라 넓은 사진의 좌우를 잘랐다(2026-08-09 갭 분석에서 적발·시정) |
| 글꼴 | `PretendardVariable.woff2` (기존 자산) | Pillow가 직접 읽는 것을 확인 |

### 저해상도 폴백 (원본의 약 40%)

```
원본 최대변 >= 1080  →  사진 레이아웃
원본 최대변 <  1080  →  텍스트 중심 레이아웃 (확대 금지)
```

확대하면 화질 저하가 그대로 보인다. **작은 사진은 안 쓰는 게 낫다.**

## 3. 문안 생성 (③)

기존 `analyzeSubtitles` 계열과 같은 **읽기 전용 분석 액션**으로 붙인다.
초안 문서를 변형하지 않으므로 되돌리기·자동저장 대상이 아니다.

```
입력   초안 제목 + 본문(215~525자) + 기관명
출력   { cover: "6~30자", cards: ["15~70자", ...2~4장], tags: [...최대 5] }
```

규격은 처음에 "표지 15자·카드 40~60자·3~4장"으로 잡았다가, 실제 모델 출력이
자연스럽게 걸치는 범위로 넓혔다. 너무 좁게 잡으면 멀쩡한 문안이 계속 거절된다.

**검증은 컨트롤러에서 한다** — 반환값을 믿지 않고 장수·글자수를 다시 확인하고,
초과하면 자르지 말고 **거절한다**. 규격 미달은 모델을 바꾸면 통과하는 일이 잦아
다음 모델로 넘어가고(Flash → Flash-Lite), 끝내 못 맞추면 시도한 모델을 모두 적어
실패시킨다. 잘린 문장이
카드에 박히면 사람이 고치기 더 번거롭다.

## 4. 후보 추천 (①)

하루 244건을 사람이 다 보게 할 수 없다. 8건으로 줄이고 사람이 3~5건을 고른다.

추천 기준 — **주민 생활에 직접 영향** > 마감·신청 기한 있음 > 구체 수치 있음 >
첨부 있음. 인사·간담회·표창 같은 행정 소식은 감점한다.

**LLM이 아니라 키워드 점수 규칙**이다(`card_picks.py`). 비용이 0이고 결과가
재현되며, 사람이 왜 올라왔는지 볼 수 있어 이 단계에는 이쪽이 낫다.

편중은 두 축으로 막는다.

- **기관당 최대 2건** — 한 기관 홍보물처럼 보이면 주민이 안 본다.
- **주제당 최대 2건** — 실측에서 폭염 주간에 8건 중 7건이 폭염 기사로 채워졌다.
  기관은 일곱 곳으로 달랐지만 주민이 보기엔 같은 소식 일곱 번이다.
- 주제가 쏠려 명단이 짧아지면 **최소 5건까지만** 상한을 푼다. 비슷한 기사로
  8칸을 억지로 메우면 고르는 데 방해만 된다.

주의 — "첨부 있음" 가점은 **첨부 존재 여부만** 본다. 원본 해상도까지 보려면
내려받아야 해서, 1080px 미만이라 실제로는 텍스트 카드가 될 기사도 가점을 받는다.

추천은 **제안일 뿐 자동 발행하지 않는다.** 최종 선택은 사람이 한다.

## 4-1. 사진-본문 불일치 — 구조로 막는다

**구현 중 실제로 겪었다.** 확인 스크립트가 대시보드에서 사진을 긁어와 카드를 만들었더니
**화재 조사 현장 사진에 공공예식장 안내문**이 붙은 카드가 나왔다. 방송사가 이런 카드를
내보내면 단순 버그가 아니라 신뢰 사고다.

주의로 막을 일이 아니라 **구조로 막는다.**

- 카드 생성의 **공개 진입점은 `draft_id`만 받는다.** 사진 바이트를 밖에서 넘기는
  경로를 공개 API로 두지 않는다.
- 사진은 반드시 **그 초안이 속한 원문의 `press_release_assets`에서만** 가져온다.
- 관리 화면 미리보기에 **원문 링크를 함께 띄워** 사람이 대조할 수 있게 한다.

`cardnews.build_card_images()`는 바이트를 받는 순수 함수라 출처를 알 수 없다.
**출처 보장은 이 함수를 부르는 통합 계층의 책임**이며, 그 계층에 회귀 테스트를 둔다.

## 5. 저장

| 대상 | 위치 | 이유 |
|---|---|---|
| 카드 이미지 | `<디스크>/cardnews/YYYY-MM-DD/<세트>/N.png` | 썸네일 디스크 캐시와 같은 방식. 재기동에도 남는다 |
| 세트 메타 | DB 신규 테이블 `card_news_sets` | 날짜·초안ID·문안·상태(초안/발행)·생성시각 |

보관은 스케줄러 유지보수의 "오래된 카드뉴스 정리" 단계가 맡는다
(`NEWS_SUMMARY_CARDNEWS_KEEP_DAYS`, 기본 30일). 하루 5세트 × 5장 × 약 300KB =
**약 7.5MB/일**. 30일 보관해도 225MB로 1GB 디스크에 여유가 있다.

## 6. 화면

| 경로 | 공개 | 내용 |
|---|---|---|
| `/card-news` | **공개** | 오늘의 카드뉴스. 좌우 스와이프, 링크 복사 |
| `/card-news?date=YYYY-MM-DD` | **공개** | 지난 날짜(최근 30일 발행분) |
| `/card-news/manage` | 관리자 | 후보 확정 · 문안 수정 · 재생성 · 발행 · 발행 내리기 · 삭제 |
| `/card-news/<id>/<n>.png` | 발행분만 공개 | 카드 이미지(미발행은 404) |

공개 경로는 기존 `PUBLIC_READ_ENDPOINTS`에 넣는다(보기는 누구나, 변경은 관리자만).

**퍼가기**가 핵심이다. 카톡·밴드로 옮겨지는 것이 실제 확산 경로이므로
링크 복사 버튼과 카드 이미지 개별 저장을 반드시 넣는다. OG 태그도 넣어
카톡에 링크를 붙이면 표지 카드가 미리보기로 뜨게 한다.

## 7. 메모리 — 반드시 지킬 것

1080 합성은 썸네일(0.19MB)보다 무겁다. 세 가지를 지킨다.

1. **수집 회차 밖에서 생성**한다 — 회차와 겹치면 피크가 합쳐진다.
2. 합성 직후 **`_release_free_heap()`** 를 부른다(썸네일과 동일).
3. 한 번에 한 세트씩 처리하고, 세트 사이에 결과를 **즉시 디스크로 내린다.**

생성 전후 `/healthz`의 `process_memory_mb`로 실측해 기록한다.

## 8. 구현 순서

| 순서 | 내용 | 검증 방법 |
|---|---|---|
| 1 | 카드 합성 모듈 (`cardnews.py`) | 저해상도·사진없음·긴제목 등 경계 입력 단위 테스트 |
| 2 | 문안 생성 액션 + 검증 | 잘못된 반환(장수 초과·빈 문자열) 거절 테스트 |
| 3 | DB 테이블·저장 경로 | 재기동 후에도 카드가 남는지 |
| 4 | 관리 화면 (확정·수정·재생성) | 사람이 실제로 한 세트를 끝까지 만들어 봄 |
| 5 | 공개 화면 + OG 태그 | 카톡에 링크 붙여 미리보기 확인 |
| 6 | 후보 추천 | 하루치로 추천 8건이 납득되는지 눈으로 확인 |

**1번부터 하는 이유** — 가장 불확실한 것이 합성 품질이고, 이미 시안으로 절반
검증됐다. 여기서 막히면 나머지가 의미 없으므로 먼저 끝낸다.

## 9. 하지 않는 것

- 자동 발행 (사람 확인 필수)
- 영상·모션
- 구독자 관리·푸시
- 인스타·밴드 자동 연동 — **이미지 파일을 내려받아 사람이 올린다.** 반응을 보고
  나중에 판단한다
