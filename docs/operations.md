# 운영 방법

## 어디서 쓰나

평소 운영은 **배포본**에서 합니다 — `https://news-express-1.onrender.com`.
수집은 그쪽에서 매시 자동으로 돕니다.

로컬은 개발·점검용입니다.

```powershell
cd "C:\Users\seung\news summary"
.\scripts\setup.ps1
.\scripts\run_review_app.ps1
```

브라우저에서 `http://127.0.0.1:5000`을 엽니다.

## 매일 쓰는 흐름

1. 홈 화면에서 자동 수집 상태와 기관별 진행을 확인합니다(설정된 수집처 **28곳**,
   그중 **27곳 활성** — 강진은 수집 실패로 꺼 둔 상태입니다).
2. 필요하면 `수동 재수집`으로 전체 기관을 다시 확인합니다.
3. `주의 필요` 또는 `기관별 수집 상태`를 먼저 열어 위험 신호가 있는 초안부터 검수합니다.
4. 각 초안을 열어 원문과 초안을 비교하고, 필요하면 Gemini 다듬기 버튼으로 다시 정리합니다.
5. 문제가 없는 초안은 `승인`으로 바꿉니다.

## 카드뉴스 만들기

주민에게 내보내는 카드뉴스는 별도 화면에서 만듭니다. **기사 한 건이 카드 한 장**입니다.

1. 상단 메뉴 `카드뉴스` → 오른쪽 위 **`카드 만들기`**(로그인한 상태에서만 보입니다).
2. 추천 후보 중 **3~5건**을 골라 `카드 만들기`를 누릅니다.
3. 문안을 확인하고 필요하면 고칩니다. 글자만 고칠 때는 `저장`을 쓰세요 —
   `AI로 다시 만들기`는 손질한 글자를 덮고 한도도 깎습니다.
4. **`발행하기`** — 이때부터 주민에게 보입니다.
5. `/card-news` 링크를 카톡·밴드에 공유합니다(카드가 미리보기로 뜹니다).

알아 두면 좋은 것.

- **`Gemini Lite` 배지**가 붙은 세트는 예비 모델이 쓴 문안입니다. 주 모델의 무료 한도
  (하루 20회)가 찼을 때 넘어갑니다. 소제목이 명사로 끝나고 본문이 길어지는 경향이
  있으니, 손보거나 한도가 도는 다음 날 다시 만드세요.
- **`옛 형식 N장`** 배지는 한 장 카드로 바뀌기 전에 만든 세트입니다.
  `다시 그리기`를 누르면 문안 그대로 한 장으로 다시 그립니다(AI를 안 부릅니다).
  그림이 바뀌므로 검수 대기로 내려가니 **확인 후 다시 발행**하세요.
- 카드에 사진이 없으면 그 이유를 만든 직후 안내로 알려 줍니다(첨부가 없었는지,
  내려받아 본 사진이 문턱에 걸렸는지).

## 상단 메뉴

- `대시보드`: 수집 상태, 기관별 상태, 주의 필요 건수를 확인하는 첫 화면입니다.
- `Gemini 사용량`: 로컬 성공 호출 수와 Google AI Studio 사용량 확인 링크를 보는 화면입니다.
- `초안 검수`: 전체 초안과 승인/반려/주의 필요 필터를 다루는 작업 화면입니다.
- `카드뉴스`: 주민에게 보이는 공개 화면입니다. 로그인 상태면 오른쪽 위에
  `카드 만들기`가 보이고, 거기서 관리 화면으로 갑니다.
- `기사 설정`: Gemini 기사 톤, 길이, 문장 스타일을 조정하는 설정 화면입니다.
- `운영 관리`: 백업·복구, 자동 수집 토글, 로그를 다룹니다. **관리자 로그인만으로는
  안 열리고** 운영 전용 비밀번호를 한 번 더 확인합니다.

승인된 기사는 별도 상단 메뉴 대신 대시보드의 `승인 완료` 카드나 초안 검수 화면의 `승인` 필터에서 확인합니다.

## 검수 우선순위

홈 화면의 `주의 필요`는 아래 표시가 붙은 초안을 먼저 모아 보여줍니다. **다섯 가지가
전부이고**, 각각이 붙는 조건은 `review_flags`가 정합니다.

| 표시 | 언제 붙나 |
|---|---|
| `게시일 확인` | 게시일이 없거나, 파싱이 안 되거나, 앞에 담당자명 같은 문구가 붙은 경우 |
| `중복 제목` | 같은 제목이 중복 수집된 경우 |
| `AI 확인` | 규칙 기반이거나 AI 오류 후 생성된 초안 |
| `원문 검증 확인` | 제목 핵심어가 0개이거나 기존 수집 원문으로 표시된 경우 |
| `형식 확인` | 제목이나 본문이 `[뉴스 단신]`으로 시작하거나 본문이 제목을 그대로 반복하는 경우 |

목록 화면에서는 `오늘 기사`, `신청·모집`, `행사·교육`, `지원·예산`, `게시일 확인`
필터로 먼저 볼 기사를 좁힐 수 있습니다.

## 기관별 상태

홈 화면의 `기관별 수집 상태`는 활성 27개 기관별 누적 수집 건수, 최근 수집 시간, 최근 제목, 수집량 부족 또는 게시일 확인 필요 여부를 보여줍니다.
특정 기관 카드를 누르면 해당 기관의 검수 대기 기사만 볼 수 있으며, 목록은 게시일 기준 최신순으로 정렬됩니다.

## Gemini 사용량

상단 메뉴의 `Gemini 사용량`은 KBC NEWS EXPRESS DB에 저장된 성공 호출을 기준으로 오늘 초안 생성, 오늘 다듬기, 전체 Gemini 생성 건수를 보여줍니다.
무료 key의 정확한 남은 요청 수, 분당 제한, 일일 제한은 Google AI Studio의 `Usage and Limits` 화면에서 확인합니다.
Google 공식 문서상 Gemini API rate limit은 요청/토큰/일일 요청 등 여러 축으로 적용되며, 활성 제한은 AI Studio에서 확인하는 방식입니다.

## 운영 로그

앱은 기본적으로 `data/logs/news_summary.log`에 운영 로그를 남깁니다.
로그에는 서버 시작, 수동 재수집 요청, 기관별 수집 성공/실패, Gemini 모델 실패, 초안 생성 보류, Gemini 다듬기 실패, 승인 기사 내보내기, 웹 예외가 기록됩니다.

로그 파일은 자동으로 회전됩니다.

```text
NEWS_SUMMARY_LOG_DIR=data/logs
NEWS_SUMMARY_LOG_LEVEL=INFO
NEWS_SUMMARY_LOG_MAX_BYTES=2000000
NEWS_SUMMARY_LOG_BACKUP_COUNT=5
```

문제가 발생하면 `data/logs/news_summary.log`에서 가장 최근의 `WARNING` 또는 `ERROR` 줄부터 보면 됩니다.

```powershell
.\scripts\collect_and_draft.ps1

```

## 인공지능 API

`.env`에 `GEMINI_API_KEY`를 넣으면 Gemini 기사 초안을 사용할 수 있습니다.

키가 없어도 규칙 기반 초안을 만들기 때문에 수집과 검수 흐름은 그대로 확인할 수 있습니다.
