## 결정

`scripts/safe_deploy.py`가 푸시에 성공하면 Render 배포 훅을 직접 부른다.

| 항목 | 내용 |
|---|---|
| 활성 조건 | `RENDER_DEPLOY_HOOK_URL`이 환경변수 또는 `.gitignore`된 `.env`에 있을 때만. 없으면 기존 동작 그대로 |
| 비밀 | URL에 키가 들어 있다. 저장소·로그·종료 메시지에 넣지 않는다(예외 메시지도 종류만 출력) |
| `[skip render]` | 훅은 Render의 skip 판정을 거치지 않으므로 HEAD 커밋 메시지에 `[skip render]`·`[render skip]`·`[skip deploy]`·`[deploy skip]`이 있으면 훅도 부르지 않는다 |
| 순서 | 수집 회차·정각 점검을 통과해 푸시한 뒤에만 호출한다(빌드가 회차를 덮치는 사고 방지) |
| 실패 | 푸시 실패는 git 종료 코드를 그대로 돌려준다. 훅 실패는 종료 코드 3(푸시는 끝난 상태, 수동 배포 안내) |
| 호출 방식 | 훅 URL에 `GET`. `ref`는 붙이지 않는다 — Render가 서비스 브랜치의 최신 커밋을 배포한다 |

## 하지 않는 것

- **푸시할 것이 없을 때의 훅 생략** — 넣지 않았다. 푸시는 됐는데 배포가 안 된 커밋을 `safe_deploy`를 다시 돌려
  배포하는 복구 경로가 되기 때문이다. 대가로 습관적 재실행은 재배포가 된다(README에 명시).
- **배포 반영 폴링** — 이번 범위가 아니다. 반영 확인은 `/healthz`의 `commit`으로 한다.
- 훅 URL을 코드가 Render 화면에서 읽어 오는 일 — 비밀이라 사용자가 `.env`에 직접 넣는다.

## 검증

- `tests/test_safe_deploy.py` 11건: 푸시 후 호출, skip 마커 4종, URL 미설정, `.env`에서 읽기, 푸시 실패 시
  미호출, HTTP 오류·네트워크 오류 시 종료 코드 3과 키 비노출, 수집 회차 점검이 훅보다 먼저 거절.
- 변이 검증: 예외 메시지를 그대로 출력하게 바꾸면 키 비노출 테스트가 실패함을 확인하고 되돌렸다.
- 실제 훅 호출은 사용자가 URL을 `.env`에 넣은 뒤에야 가능하다 — 그 첫 푸시가 종단 검증이다.

## 한계 · 되돌리는 법

- 자동 배포가 복구되면 `RENDER_DEPLOY_HOOK_URL`을 지운다. 둘 다 켜 두면 같은 커밋이 두 번 배포된다.
- 훅 키가 유출되면 Render Settings › Deploy Hook에서 Regenerate 한다.
