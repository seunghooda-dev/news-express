# 카드뉴스 발행 (card-news) — Plan

- **작성일**: 2026-08-09
- **상태**: Plan 확정 (2026-08-09 사용자 결정 반영)
- **결정**: 전달은 **자체 웹 페이지 먼저**, 분량은 **하루 엄선 3~5건**
- **한 줄**: 매일 만들어지는 기사 초안과 첨부 이미지를 카드뉴스로 묶어 지역 주민에게 전달한다.

## 1. 왜 지금 할 수 있나 — 재료 실측

계획 전에 실제 데이터를 재봤다. 추정이 아니라 측정값이다.

| 재료 | 실측 | 판단 |
|---|---|---|
| 초안 분량 | 215~525자 · 3~6문장 | **카드 3~5장에 딱 맞는다** |
| 이미지 보유율 | 최근 50건 중 **50건(100%)** | 이미지 없는 예외를 걱정할 필요 거의 없음 |
| 기사당 첨부 수 | 1장 19건 · 2장 10건 · 3장 12건 · 4장 이상 9건 | 표지 1 + 본문 2~3장 확보 가능 |
| 원본 해상도 | 5건 중 **3건만 1080px 이상**(3500×2625 등), 2건 부족(980×735, 600×400) | **40%는 저해상도 대비 필요** |
| 이미지 방향 | 표본 8건 **전부 가로형**(1.33~1.92) | 정사각/세로 카드에 그대로 못 넣는다 |

이미 가진 것 — 초안 생성(Gemini), 이미지 수집·저장, 축소·캐시 파이프라인(Pillow),
웹 화면, 스케줄러. **새로 만들 것은 "문안 요약 → 카드 합성 → 전달" 세 단계뿐이다.**

## 2. 목표와 비목표

**목표**

- 매일 승인된 기사에서 카드뉴스 세트를 자동 생성한다.
- 주민이 별도 앱 설치 없이 볼 수 있고, 퍼가기 쉬워야 한다.
- 기자·관리자가 발행 전에 확인·수정할 수 있어야 한다(현행 검수 흐름과 동일 철학).

**비목표 (이번엔 안 한다)**

- 영상·모션 카드
- 개인화 추천·구독자 관리
- 댓글·반응 수집

## 3. 세 단계

### 3-1. 카드 문안 생성

초안 본문(215~525자)을 카드용으로 다시 쓴다. 기존 `analyzeSubtitles` 계열과 같은
**읽기 전용 분석 액션**으로 붙인다 — 초안 원문을 건드리지 않는다.

```
입력  초안 제목 + 본문
출력  표지 문구(15자 내외) + 본문 카드 3~4장(장당 40~60자) + 해시태그
```

### 3-2. 카드 이미지 합성

Pillow로 1080×1080(또는 1080×1350) 카드를 만든다.

**가로 이미지를 정사각에 넣는 문제**의 해법은 크롭이 아니라 **상하 분할**이다.
상단 60%에 이미지(가로 그대로), 하단 40%에 문구. 인물·현장 사진이 잘리지 않는다.

**저해상도 40% 대비** — 원본이 1080에 못 미치면 이미지를 키우지 않고
**텍스트 중심 레이아웃**으로 전환한다(이미지는 작게 배치하거나 배경 블러).
확대는 화질 저하가 바로 보인다.

### 3-3. 전달 — **여기가 결정 필요 지점**

| 채널 | 지역 주민 도달 | 비용 | 자동 발행 | 걸림돌 |
|---|---|---|---|---|
| **자체 웹 "오늘의 카드뉴스"** | 링크 공유로 확산 | 0원 | **가능** | 없음 — 이미 있는 웹에 화면 하나 |
| 네이버 밴드 | **지역 커뮤니티에 가장 강함** | 0원 | 어려움 | 공개 API 제한적 → 사람이 올림 |
| 인스타그램 | 젊은 층 | 0원 | 조건부 | Meta 비즈니스 심사·연동 필요 |
| 카카오톡 채널 | **가장 높음** | **건당 과금** | 가능 | 알림톡 심사·발송 비용 |

**권고 순서** — ①자체 웹으로 먼저 만든다(비용 0, 심사 0, 이번 주 가능) →
②이미지 파일을 내려받아 밴드·인스타에 사람이 올린다 → ③반응을 보고 그때
자동 연동이나 카카오 채널에 투자한다.

이유는 셋이다. 카드 **생성**은 어느 채널이든 똑같이 필요하고, 웹은 심사 대기가
없어 가장 빨리 주민 반응을 볼 수 있으며, 실패해도 버릴 것이 없다.

## 4. 위험과 대비

| 위험 | 대비 |
|---|---|
| 원본 40%가 저해상도 | 텍스트 중심 레이아웃 폴백(확대 금지) |
| 가로 사진뿐 | 상하 분할 레이아웃(크롭 안 함) |
| 지자체 사진 저작권 | **출처를 카드에 명시**(기관명), 원문 링크 병기 |
| AI 문안 오류 | 발행 전 검수 단계 유지 — 자동 발행 금지 |
| 메모리 | 1080 합성은 썸네일보다 무겁다. **수집 회차 밖에서 생성**하고 결과를 디스크에 저장(현행 썸네일 캐시와 동일 방식) |

메모리는 특히 주의한다. 썸네일 1건이 0.19MB인데 1080 합성은 그보다 크다.
생성 즉시 디스크에 저장하고 `_release_free_heap()`을 같은 방식으로 부른다.

## 5. 성공 기준

1. 승인 기사 하나로 카드 세트(표지+3장)가 **1분 안에** 만들어진다.
2. 저해상도 기사에서도 **깨진 카드가 나오지 않는다**(폴백 동작).
3. 발행 화면에서 사람이 문안을 고칠 수 있다.
4. 카드 생성이 기존 수집·초안 파이프라인의 지표(완주 시간·메모리)를 **악화시키지 않는다**.

## 6. 시안으로 확인한 것 (2026-08-09)

계획만 쓰지 않고 **실제 기사·실제 사진으로 카드를 만들어 봤다.** 세 가지가 확인됐다.

1. **글꼴 문제가 없다.** Pillow가 이미 자체 호스팅 중인 `PretendardVariable.woff2`를
   그대로 읽는다. 한글이 정상 조판된다 — **글꼴 파일을 새로 넣을 필요가 없다.**
2. **상하 분할 레이아웃이 통한다.** 가로 사진을 자르지 않고 상단에 얹고 하단에
   문구를 두니 인물·현장이 살아 있다.
3. **AI 문안 단계가 필수임이 실증됐다.** 초안 문장을 그대로 넣으니 한 카드에
   4줄이 넘어가 카드뉴스가 아니라 그냥 기사가 됐다. 장당 40~60자로 다시 쓰는
   단계가 반드시 있어야 한다.
