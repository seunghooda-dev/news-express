# 영광군청 로컬 중계 편입 계획 (2026-11-18)

## 배경

영광군청(`yeonggwang-county`)은 서버(Render 싱가포르)에서 **2026-11-17 16:08이 마지막 성공**이고
이후 매시 :08 회차마다 `ConnectTimeout`(TLS 연결 시간 초과)으로 실패했다. 2026-11-18 11:00 기준
최근 7일 실패 54건 전부 "일시 장애 · 외부 사이트 응답 지연"이고 구조 문제(선택자·HTTP 오류)는 0건이다.

같은 시각 이 PC(한국 IP)에서 같은 설정으로 `collect_source_with_fallback`을 두 번 돌리면 매번 10건이
수집된다(약 42초, 읽기 전용 실측 11:03). 즉 사이트·주소·선택자는 정상이고 **서버 출구 IP만 막힌 것**이다.
강진(8/26)·광주 남구(9/1)·구례(9/6)와 같은 증상이지만, 영광은 어제까지 정상이던 **새 차단**이라
일시 제한일 가능성도 남는다(직접 증명은 못 했다).

## 결정

이미 검증된 방식 그대로 **로컬 중계에 편입**한다. 관찰만 하자던 기준(07:08·08:08 회차)을 넘겨
18시간 연속 0회 성공이므로 일시 지연으로 보기 어렵다고 판단했다.

| 항목 | 내용 |
|---|---|
| `config/municipalities.yaml` | `yeonggwang-county` `enabled: false`. 켜 두면 서버가 매시간 실패를 쌓고 재검증까지 끌려가 회차 완주를 막는다(2026-07-30 강진 실사고). 주소·선택자는 그대로 둬 중계가 읽는다. |
| 로컬 중계 `SOURCE_IDS` (저장소 밖) | `yeonggwang-county` 추가. 서버의 초안 생성 쿼리는 소스 `enabled`를 보지 않으므로 원문만 넣으면 초안·카드는 서버가 만든다. |
| `tests/test_web.py` | 커버리지 테스트 3건 갱신 — 활성 25→24, 비활성 3→4(`["광주 남구","구례","강진","영광"]`), 초안 한도는 `max(활성×10, 250)`라 24×10=240이 바닥값 250에 걸려 **250 그대로**. |
| `REQUIRED_SOURCE_COVERAGE` | 변경 없음. 필수 목록에 남겨 둬 운영 화면이 계속 "필수 기관 4곳 비활성화" 경고로 상기시킨다. |

## 되돌리는 법

서버 차단이 풀리면(예: 중계를 잠시 빼고 서버 회차에서 영광이 성공하는지 본다) `enabled: true`로 되돌리고
중계 `SOURCE_IDS`에서 뺀다. 같은 3곳(커버리지 테스트)을 반대로 갱신한다. URL 중복은
`add_press_release`가 막으므로 두 경로가 겹쳐도 안전하다.

## 한계 · 주의

- **서버에 반영되려면 배포가 필요하다.** `enabled: false`는 설정 파일 변경이라 Render가 새 커밋을 받아야 한다
  (2026-11-18 11:01 현재 서버는 `d0fd253`에 머물러 있고 `a50373d`도 미반영). 중계 `SOURCE_IDS`는 저장소 밖이라
  즉시 효과가 있다 — 배포 전에도 영광 원문은 정시마다 들어온다.
- 보관 3영업일(`collection_retention_cutoff_date`) 밖으로 지난 글은 복구되지 않는다. 11/17 16:08 이후 새 글이
  없었다면 손실도 없다(로컬 목록의 최신 글이 11/17이다).
- 이 PC가 꺼져 있으면 영광도 멈춘다. 중계 감시(`relay-heartbeat.plan.md`)가 3시간 넘게 안 돌면 서비스 상태에 경고한다.
- 중계 한 회차가 4곳이 되어 길어진다(약 2~3분). 작업 제한 15분 안이다.
