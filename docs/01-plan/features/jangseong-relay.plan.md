# 장성군청 로컬 중계 편입 계획 (2026-11-23)

## 배경

2026-11-23 12:59 상세 헬스체크가 `source_collection_status: error`("미복구 수집 실패 기관 1곳")였다. 원인은
장성군청(`jangseong-county`)이다. 서버(Render 싱가포르)에서 목록 주소
`https://www.jangseong.go.kr/home/www/news/jangseong/bodo` 요청이 **HTTP 400 Bad Request**로 실패하고,
약 50회차(대략 11/21 낮부터 50시간) 연속이며 최근 24시간 실패는 180건(회차당 최초 1 + 자동 재검증 2)이다.

같은 시각 이 PC(한국 IP)에서 같은 설정으로 `collect_source_with_fallback`을 돌리면 15건이 수집된다
(읽기 전용 실측 12:59, 최신 글 11/19). 즉 사이트·주소·선택자는 정상이고 **서버 출구 IP만 막힌 것**이다.
강진·남구·구례·영광과 같은 증상이다. 영광은 응답이 타임아웃이었고 장성은 400이라 차단 방식이 다르지만,
같은 설정이 한국 IP에서 되고 서버에서만 안 되므로 같은 처방을 쓴다(직접 증명은 못 했다).

장성의 최신 글이 11/19라서 서버가 막힌 11/21 이후 놓친 글은 아직 없다. 새 글이 올라오기 전에 편입한다.

이미 검증된 방식 그대로 **로컬 중계에 편입**한다. 계획·검증은 영광 편입(`yeonggwang-relay.plan.md`)과 같다.

## 되돌리는 법

서버 차단이 풀리면(중계를 잠시 빼고 서버 회차에서 장성이 성공하는지 본다) `enabled: true`로 되돌리고 중계
`SOURCE_IDS`에서 뺀다. 같은 3곳(커버리지 테스트)을 반대로 갱신한다. URL 중복은 `add_press_release`가 막으므로
두 경로가 겹쳐도 안전하다.

## 한계 · 주의

- **서버에 반영되려면 배포가 필요하다.** `enabled: false`는 설정 파일 변경이다. 배포 전에도 중계가 정시마다 장성을
  채우므로 데이터는 비지 않는다. 푸시는 `scripts/safe_deploy.py`로 하고 훅이 배포를 시작한다.
- 보관 3영업일 밖으로 지난 글은 복구되지 않는다. 서버가 막힌 11/21 이후 새 글은 없었다.
- 이 PC가 꺼져 있으면 장성도 멈춘다. 중계 감시(`relay-heartbeat.plan.md`)가 3시간 넘게 안 돌면 서비스 상태에 경고한다.
- 중계 한 회차가 5곳이 되어 길어진다(약 3분). 작업 제한 15분·회차 마감 420초 안이다.
- **차단이 일주일에 두 곳씩 늘고 있다**(영광 11/17, 장성 11/21). 중계가 노트북 한 대에 걸려 있어, 한국 IP를 경유하는
  프록시나 한국 서버로 중계를 노트북에서 분리하는 방안은 별도 결정이 필요하다(이번 범위 밖).
