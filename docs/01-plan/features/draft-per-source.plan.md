# 기관별 즉시 초안 변환 계획 (2026-11-25)

## 배경 — "미변환 기사"가 왜 생기나

운영 화면·헬스체크가 매시 같은 시각에 "오늘 수집 원문 중 초안 미변환 N건"(warning)을 띄웠다. 2026-11-25 15:00 회차를
30초 간격으로 기록해 보니(읽기 전용, `/healthz/details`) 원인은 **고장이 아니라 순서**였다.

| 시각 | 단계 | 미변환 |
|---|---|---|
| 15:00~15:11 | 23개 기관을 **전부 수집**(기관마다 새 글을 저장만 한다) | 7 → 10 → 14 → 18로 쌓임 |
| 15:11~15:14 | 그제서야 **초안 변환**(글당 약 8초) | 18 → 15 → 9 → 4 → 0 |
| 15:14 | 회차 종료 | 0 (정상) |

- 초안 생성 실패는 0건(`gemini_failure_total`), 쿨다운 없음. 이전 날짜에 남은 미변환도 0건(전 기관 페이지 확인).
- 즉 `collect_and_draft_cycle`이 `collect_enabled_sources`(전 기관)를 다 끝낸 뒤 `draft_pending_releases`를 한 번 부르는
  구조라, 먼저 수집된 글(예: 순천·나주·여수)이 **회차 끝까지 최대 약 11분** 미변환으로 남는다. 매시 약 14분, 하루의
  약 4분의 1이 "미변환 경고" 시간이다. 로컬 중계가 :00~:03에 넣은 글도 같은 회차 끝에 변환된다.
- 회차 전체 길이(약 14분)는 그대로다 — 초안 변환 시간이 앞으로 당겨질 뿐 늘지 않는다.

## 결정

각 기관의 수집·저장이 끝나는 즉시 그 새 글을 변환한다(기관별 인라인 변환).

| 항목 | 내용 |
|---|---|
| `collect_enabled_sources` | 선택 인자 `after_source_inserted(source, new_count) -> list[str]`를 받는다. 기관의 새 글 저장·상태 기록이 끝난 뒤, **새로 저장된 글이 있을 때만** 호출한다. 기본값 `None`이면 종전과 같다(CLI·수동 수집·시험이 영향 없음). |
| 호출 보호 | 콜백이 던지는 예외는 잡아 로그만 남기고 다음 기관 수집을 계속한다 — 변환 문제로 나머지 기관 수집이 중단되면 안 된다. |
| `collect_and_draft_cycle` | 콜백으로 `draft_pending_releases(store, limit=25, require_gemini=...)`를 넘긴다(대기열 소진과 같은 25건 한도). 한도 밖·실패·재검증으로 회복된 기관의 글은 **종전의 회차 끝 일괄 변환이 그대로 맡는다**(안전망 유지). |
| 쿼터 | 변환이 쿼터 오류를 만나면 기존 로직대로 쿨다운을 걸고 멈춘다. 이후 기관의 변환 호출은 쿨다운 메시지만 돌려주고 수집은 계속한다. |
| 진행 표시 | 변환 중에는 `phase="collecting"`·`"N/M 기관 초안 변환 중"` 메시지로 알린다. |

## 하지 않는 것

- 미변환 경고의 문구·판정 규칙 변경 — 변환 지연 창이 1분 안쪽으로 줄어 따로 손댈 이유가 없다. 다시 길어지면 그때 본다.
- 병렬 변환·별도 스레드 — 회차 길이는 그대로이므로 동시성 위험을 들일 이유가 없다.
- 변환 한도·모델·재시도 정책 변경.

## 검증

- 시험 먼저: 콜백 호출 조건(새 글이 있는 기관만), 호출 순서(기관 A 변환이 기관 B 수집보다 먼저), 콜백 예외 격리,
  `collect_and_draft_cycle` 통합(수집·변환이 번갈아 일어남, 회차 끝 일괄 변환이 남은 것을 맡음).
- 배포 뒤 같은 방식으로 한 회차를 기록해 미변환이 쌓이지 않는지 확인한다(기대: 최대 몇 건이 수 초~1분 머묾).

## 되돌리는 법

`collect_and_draft_cycle`의 콜백 인자를 빼면 종전 동작이다(`collect_enabled_sources`의 선택 인자는 무해하게 남는다).

## 독립 검토 반영 (읽기 전용 검토자 1명)

- **쿨다운 중 반복 안내 제거** — 쿨다운이 걸린 동안 새 글이 있는 기관마다 같은 안내 메시지가 쌓여 상태 꼬리(최근 12줄)를 가렸다. 인라인 호출은
  `require_gemini`이고 쿨다운이면 아무것도 하지 않고(Gemini도 안 부른다), 안내는 회차 끝 일괄 변환이 한 번만 낸다.
- **대체 초안 라벨 순서** — Gemini 실패 뒤 대체 초안(`gemini-…:gemini-error:…:rule-based`)이 모델 이름에 gemini가 들어 있어 "Gemini Lite"로
  표시됐다(이전부터 있던 문제). `model_label`·`model_badge_class`가 규칙 기반을 먼저 판정해 "규칙 기반"(경고 색)으로 나온다. 원문 목록·상세에는 다른
  신호(AI 확인 플래그)가 없어 이 배지가 유일한 단서다.
- **시험 보강** — 회차 끝 일괄 변환이 실제로 일하는지(마지막 기관 인라인 실패 → 일괄 변환이 변환), 인라인 호출이 `require_gemini`를 넘기는지.
- **알려진 한계(이번 범위 밖)** — Gemini 클라이언트에 타임아웃이 없어(`genai.Client(api_key=…)`, google-genai 기본 `timeout=None`) 응답 없이 걸린 호출은
  이론상 무한 대기다. 예전에는 모든 기관 수집이 끝난 뒤에 걸렸지만 이제는 기관 k의 인라인 변환에서 걸리면 k+1 이후 수집이 그 회차에서 빠진다. 이전부터 있던
  위험의 영향 범위가 늘어난 것이라 별도 작업으로 다루는 것이 맞다(`HttpOptions(timeout=…)`).

## 같은 날 함께 처리한 요청 — 글마다 붙는 모델 배지 숨김 (2026-11-25)

사용자가 "기사마다 Gemini Lite라고 뜨는 것을 지워 달라"(15:16), 이어서 "Flash도 없애 달라, 그런 것들은 불필요하다"(15:17)고 했다.

- **숨기는 것**: Gemini가 정상으로 쓴 글의 모델 배지 — 모델 문자열이 `…:gemini`(생성) 또는 `…:gemini-refine`(다듬기)인 경우.
  Lite·Flash·그 밖의 Gemini 모델을 구분하지 않는다. `web.show_model_badge(model)`이 판정하고 Jinja 전역으로 등록했다.
- **남기는 것**: 규칙 기반(`…:rule-based`), OpenAI, 모델 미상, Gemini 실패 뒤 대체 초안(`…:gemini-error…`). 이 글들은 모델이 못 써서 만든
  초안이라 검수자가 눈치채야 하는 **이상 신호**다. 이것까지 지우길 원하면 `show_model_badge`를 항상 False로 바꾸면 된다.
- **적용 화면(8곳)**: 대시보드 초안 목록·원문 목록, 초안 목록, 초안 상세, 기관 상세 초안·원문 목록, 원문 목록, 원문 상세.
- **건드리지 않은 것**: 모델 필터(드롭다운 "Gemini Lite"·적용 중 필터 칩) — 지우라는 대상이 글마다 붙는 배지이고 필터는 별개 기능이다.
  카드뉴스 문안의 모델 표시(`card_news_manage.html`)는 "어느 모델이 쓴 문안인지"를 일부러 보이게 한 기능(`test_cardnews_web`)이라 그대로 둔다.
  Gemini 사용량 화면의 모델별 집계도 그대로다.
- **시험**: `show_model_badge` 단위 시험과, Lite·Flash·규칙 기반 초안을 한 기관에 넣고 8개 화면에서 Lite·Flash 배지는 없고 규칙 기반 배지만 남는지
  보는 시험. 구현 전 실패를 확인했고 템플릿 하나라도 숨김을 빼면 실패한다(변이 검증).
