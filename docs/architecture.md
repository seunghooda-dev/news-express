# 구조

## 기본 흐름

1. `collect`
   - `config/municipalities.yaml`에서 켜진 지자체 수집처를 읽습니다.
   - 구독 피드, 자료 게시판, 일반 게시판에서 보도자료 원문을 수집합니다.
   - 원문 제목과 본문 일치성을 검증한 뒤 데이터베이스에 저장합니다.

2. `draft`
   - 아직 기사 초안이 없는 수집 원문을 찾습니다.
   - 원문을 기사 생성 지시문에 넣어 방송 단신 초안을 만듭니다.
   - 생성된 초안은 검수 대기 상태로 저장합니다.

3. 검수와 내보내기
   - 검수 화면에서 원문과 생성 초안을 나란히 비교합니다.
   - 편집자는 저장, 승인, 반려, 승인 기사 내보내기를 할 수 있습니다.

4. `카드뉴스`
   - 승인 전 초안 중 점수 규칙으로 후보를 추천하고, 사람이 3~5건을 고릅니다.
   - 초안을 카드 문안(제목 + 요점 2~4개)으로 다시 쓰고 **기사 한 건을 카드 한 장**
     (1080×1350 PNG)으로 합성합니다.
   - 발행하면 `/card-news`에서 주민이 로그인 없이 봅니다.

## 주요 모듈

- `news_summary.collectors`: 구독 피드, 자료 게시판, 일반 게시판 수집기.
- `news_summary.storage`: 데이터베이스 구조와 저장 기능.
- `news_summary.writer`: 인공지능 기사 초안 생성과 규칙 기반 예비 생성.
- `news_summary.web`: 검수·운영 화면과 공개 화면(Flask).
- `news_summary.service`: 수집과 초안 생성 공통 흐름.
- `news_summary.scheduler`: 자동 수집 회차와 유지보수(백업·정리·검증).
- `news_summary.exporter`: 마크다운과 표 파일 내보내기.
- `news_summary.cli`: 명령줄 실행 진입점.

카드뉴스 계열.

- `news_summary.card_picks`: 후보 점수와 편중 차단(기관·주제당 최대 2건).
- `news_summary.cardcopy`: 초안 → 카드 문안, 규격 검증(못 맞추면 자르지 않고 거절).
- `news_summary.cardnews`: 카드 합성. **웹·DB에 의존하지 않는 순수 모듈**.
- `news_summary.cardnews_service`: 통합 계층 — **사진 출처 보장이 여기 책임**이다.
- `news_summary.asset_filters`: 로고·배너 같은 장식 이미지 판정.

보조.

- `news_summary.auth`: 관리자·운영 비밀번호.
- `news_summary.backup` / `migrate_postgres`: 백업·복구와 SQLite→Postgres 이관.
- `news_summary.memory`: 합성·축소 뒤 힙 반납.

## 안전장치

- 원문 주소와 출처는 항상 저장합니다.
- 원문과 기사 초안은 별도 테이블에 분리합니다.
- 수집 단계에서 본문 길이, 한글 비율, 제목 핵심어 일치, 홈페이지 메뉴 잡음을 검사합니다.
- 기사 생성 지시문은 원문에 없는 사실, 날짜, 숫자, 장소, 이름을 만들지 못하게 막습니다.
- 초안은 기본적으로 검수 대기 상태이며, 자동 발행은 범위에 넣지 않았습니다.
- 카드뉴스도 사람이 `발행하기`를 눌러야 주민에게 보입니다. 카드 생성 진입점은
  **`draft_id`만 받아** 사진을 밖에서 넘길 수 없습니다 — 다른 기사 사진이 섞이는
  것을 주의가 아니라 구조로 막습니다.
- 열람은 로그인 없이 열려 있고(주민 대상), **상태를 바꾸는 조작만** 로그인을
  요구합니다. 운영 관리는 그 위에 전용 비밀번호를 한 겹 더 둡니다.
